# 硬體說明：16GB VRAM＋64GB RAM

> **狀態：2026-10-07 在 RTX 5090 上模擬驗證過**（另開程式佔住顯存，讓 ComfyUI 只剩約 14.6GB 可用，比真實 16GB 卡扣掉桌面後還少一點）。
> 驗證得到的是「畫質、顯存、記憶體、能不能跑」；**真實 16GB 卡的速度沒有實測**（見「預估耗時」）。
> 測試程式與原始數據：[setup/16gb_sim/](../setup/16gb_sim/)。

適用：RTX 4080 16GB、RTX 5070 Ti 16GB、RTX 5080 16GB，搭配 64GB 系統記憶體、NVMe SSD。
記憶體只有 32GB 的請改用 [shanshiba-workflow-16gvram-32gram](https://github.com/mathruffian-dot/shanshiba-workflow-16gvram-32gram)。

## 一句話

**跟完整版（32GB 顯卡）用一模一樣的模型和設定，出來的片逐格相同。** 只要啟動 ComfyUI 時加 `--reserve-vram 1.5`（`configs\profile.cmd` 已設好），並且一次只跑一件 GPU 工作。

### 從結果學到的

1. **顯存不夠時，ComfyUI 會把放不下的模型留在記憶體、需要時再搬上顯卡，這完全不改變畫面**，只慢 1.5–4%（5090 上）。所以完整版的模型、步數、長度規則全部照用。
2. **單鏡長度不用縮**：260 格（10.8 秒）顯存峰值 14.0GB，維持 ≤12 秒。
3. **NVFP4 文字編碼器會改變結果**：同 seed 像換了一次抽卡，品質相當，但對白鏡最後 0.5 秒出現一次疊影溶接；而且在不同記憶體條件下結果也不固定。64GB 時沒必要用它。

## 設定

| 項目 | 值 |
|---|---|
| 設定檔 | `call configs\profile.cmd` |
| H3 主模型 | 剪枝 int8（`minimax_h3_ref2va_pruned_int8_convrot`） |
| 文字編碼器 | Heretic int8（`qwen3vl_32b_h3_ultra_uncensored_heretic_int8_convrot`） |
| 影片 VAE | fp16 |
| ComfyUI 啟動參數 | 加 `--reserve-vram 1.5`（VAE 解碼當機再加 `--disable-pinned-memory --disable-async-offload`） |
| 步數 | DMAD 4 步（spec 寫 `"draft": true`） |
| 單鏡長度 | ≤12 秒 |
| 原生 1080p／H3 兩段精修 | 不建議（太慢） |
| 放大 | 近景 RTX VSR、全景 FlashVSR |

其他元件（VoxCPM2、Breeze、faster-whisper、BS-RoFormer、MiniMax Music 3、Image 2.5）顯存都在 12GB 以內，照完整版用。

**一定要遵守：一次只跑一件 GPU 工作**（配音、生圖、H3、放大不要同時），`run_queue.sh` 已經會等 GPU 空出來才開工。

## 預估耗時（未實測）

模擬卡用的還是 5090 的運算單元，所以上表的秒數**不能直接當成 16GB 卡的速度**。16GB 卡的算力約 5090 的四到五成（依 NVIDIA 公開規格粗估），再加上搬資料：

| 工作 | 5090 實測 | 16GB 卡推估 |
|---|---|---|
| 5 秒鏡（124 格）DMAD | 約 1 分鐘 | 約 2–2.5 分鐘 |
| 10.8 秒鏡（260 格）DMAD | 約 2.3 分鐘 | 約 5–6 分鐘 |
| 一支 40 鏡的片 | 約 41 分鐘 | 約 1.5–2 小時 |

## 這次驗證不到的（風險）

1. **真實速度**：見上。
2. **PCIe 頻寬**：5090 是 PCIe 5.0；4080 是 4.0，搬資料比較慢。5090 上只多 1.5–4%，預期影響有限。
3. **釘選記憶體**：ComfyUI 會把約四成系統記憶體設成釘選（64GB 時約 26GB），本次模擬是 96GB 機器，數字略有不同。
4. **真實卡的驅動問題**（社群 2026-08 回報，新版 ComfyUI 是否已修不確定）：
   - ComfyUI #15488：50 系列 16GB 卡在 64GB RAM 下出現「GPU is lost」黑畫面。
   - ComfyUI #15337：VAE 解碼記憶體錯誤 → 啟動加 `--disable-pinned-memory --disable-async-offload` 繞過。

## 不建議的路

- **GGUF Q4 主模型**：H3 張量寬度 2688 不能被 256 整除，所謂 Q4_K_M 實際是 Q4_0／Q4_1，畫質損失沒人實測；既然搬資料只慢幾 %，沒必要。
- **diffusers CPU 卸載路線**：官方寫約需 75GB RAM。

## 自己驗證

有 16GB 卡的人可以跑 `setup/16gb_sim/run_test.py`（改裡面的鏡頭路徑），拿同 seed 的結果和這裡的數字比：顯存峰值應在 14–15GB、記憶體約 +33～37GB、畫面和 32GB 顯卡逐格相同（同模型時）。
